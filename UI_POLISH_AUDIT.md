### Environment and tooling decisions

- **D-001 — Browser driver fallback.** The Product Design audit workflow prefers the Codex in-app browser and then `agent-browser`. The in-app browser control is not exposed in this task and the installed shell reports `agent-browser: command not found`. The user explicitly requires the repository Playwright projects, so the audit will use the repository's pinned Playwright runtime for real-browser interaction and capture. This is a tooling variance, not a coverage exemption.
- **D-002 — Initial-audit freeze.** No UI source file may be changed until every frozen-inventory row is either inspected or explicitly blocked and the `AUDIT_COMPLETE` marker records the baseline finding IDs and count.
- **D-003 — Equivalence.** Independent action orders may share a coverage row only when the resulting DOM, presentation, persisted state, focus, feedback, URL, and available actions are shown to be equivalent. The row must name the equivalence evidence.
- **D-004 — Isolated mobile capture pages.** A first pass placed `fullPage` screenshot capture before or between later control measurements on the same emulated page. The screenshot operation can temporarily alter that page's pointer-media state, so those early target-size measurements and screenshots were not accepted as touch evidence. The audit harness now asserts coarse-pointer media after route entry, records it in every manifest, measures before capture, and uses an isolated page per route. Both themes were recaptured; all 52 final route manifests report coarse pointer true and one touch point. The superseded artifacts were overwritten at the same audit-only paths rather than treated as product evidence.
- **D-005 — Playwright WebKit touch metadata.** The official iPhone 15 project declares `hasTouch: true` and WebKit reports `(hover: none) and (pointer: coarse)` as true, but this Playwright WebKit build exposes `navigator.maxTouchPoints` as `0` rather than the profile's Chromium value `1`. Audit assertions use the exact engine-specific value while retaining the coarse-pointer and project-profile checks; this corrects the evidence harness without weakening any product expectation.
